# MTE Relay Client Flutter Plugin (CocoaPods Integration)

This guide details how to integrate the MTE Relay Client Flutter Plugin, which is specifically designed for CocoaPods-based iOS development.

**Note:** If your iOS project supports Swift Package Manager, we recommend using the alternative plugin available at [https://github.com/Eclypses/mte-relay-client-flutter.git](https://github.com/Eclypses/mte-relay-client-flutter.git) for a potentially simpler setup.

---

## 🚀 Quick Start Guide

This project includes an `example` Flutter application. It's an excellent reference for how to configure and use the plugin within your own project.

### 📋 Prerequisites

*   Flutter SDK (stable channel, up-to-date)
*   Xcode (latest version recommended)
*   CocoaPods (latest version recommended)
*   Access to the `mte-relay-client-flutter-pod.git` and `mte-relay-client-ios.git` repositories.

### 🛠️ Setup Steps

Follow these steps carefully to integrate the plugin into your Flutter project.

#### 1. Add the Plugin to your `pubspec.yaml`

In your Flutter project's `pubspec.yaml` file, add the `mte_relay_client_plugin` under `dependencies`:

```yaml
dependencies:
  mte_relay_client_plugin:
    git:
      url: https://github.com/Eclypses/mte-relay-client-flutter-pod.git
      ref: 4.3.1 # Use the specific tag for the desired plugin version
```

**Explanation:** This tells Flutter to fetch your plugin directly from its Git repository at the specified tag.

#### 2. Update the iOS `Podfile`

Navigate to the `ios/` directory of your Flutter project. Open the `Podfile` and ensure it includes the necessary configurations for your `MteRelay` iOS library.

Here's an example of a well-structured `Podfile`. **Adjust paths and versions as required for your specific situation.**

```ruby
# Podfile for Flutter iOS integration
# Generated by Flutter; typically do not modify unless necessary.

# Specify CocoaPods' main spec repository
source 'https://cdn.cocoapods.org/'

# Minimum iOS deployment target for your app
platform :ios, '16.0'

# Disable CocoaPods analytics for faster build times
ENV['COCOAPODS_DISABLE_STATS'] = 'true'

# Define Xcode project build configurations
project 'Runner', {
  'Debug' => :debug,
  'Profile' => :release,
  'Release' => :release,
}

# --- Flutter specific setup (DO NOT MODIFY) ---
def flutter_root
  generated_xcode_build_settings_path = File.expand_path(File.join('..', 'Flutter', 'Generated.xcconfig'), __FILE__)
  unless File.exist?(generated_xcode_build_settings_path)
    raise "#{generated_xcode_build_settings_path} must exist. If you're running pod install manually, make sure flutter pub get is executed first"
  end

  File.foreach(generated_xcode_build_settings_path) do |line|
    matches = line.match(/FLUTTER_ROOT\=(.*)/)
    return matches[1].strip if matches
  end
  raise "FLUTTER_ROOT not found in #{generated_xcode_build_settings_path}. Try deleting Generated.xcconfig, then run flutter pub get"
end

require File.expand_path(File.join('packages', 'flutter_tools', 'bin', 'podhelper'), flutter_root)

flutter_ios_podfile_setup
# --- End Flutter specific setup ---


target 'Runner' do
  use_frameworks! # Crucial for Swift/dynamic libraries

  # Explicitly add the MteRelay pod from its Git source.
  # This ensures CocoaPods finds and integrates your MteRelay iOS library.
  pod 'MteRelay', :git => 'https://github.com/Eclypses/mte-relay-client-ios.git', :tag => '4.4.7'

  # Install all Flutter plugin pods. This line will integrate `mte_relay_client_plugin`.
  flutter_install_all_ios_pods File.dirname(File.realpath(__FILE__))

  # Target for unit tests
  target 'RunnerTests' do
    inherit! :search_paths
  end
end

# Post-installation hooks for Flutter-specific build settings
post_install do |installer|
  installer.pods_project.targets.each do |target|
    flutter_additional_ios_build_settings(target)
  end
end
```

**Important Notes for the `Podfile`:**

*   **`use_frameworks!`**: This is essential for modern Swift-based pods and dynamic frameworks.
*   **`pod 'MteRelay', :git => ..., :tag => ...`**: This line directly specifies how CocoaPods should fetch your core `MteRelay` iOS library. The `:tag` value must exactly match the `s.version` in the `MteRelay.podspec` file at that specific Git tag in `https://github.com/Eclypses/mte-relay-client-ios.git`.
*   **`source 'https://github.com/Eclypses/mte-relay-client-ios.git'` (Removed):** This line was removed from the example. It is typically used for *private CocoaPods spec repositories*, not for directly referencing a Git project. If your `mte-relay-client-ios.git` is not a private spec repo, removing this line prevents potential confusion for CocoaPods' dependency resolver.

#### 3. Clean and Rebuild Your Project

Execute these commands from the **root directory of your Flutter project** to ensure all caches are cleared and dependencies are correctly installed:

```bash
# 1. Clean Flutter build artifacts
flutter clean

# 2. Fetch Flutter package dependencies (will also update symlinks)
flutter pub get

# 3. Aggressively remove existing iOS Pods and lock file to ensure a fresh install
#    (Optional: Add `pod cache clean --all` if issues persist after this step)
rm -rf ios/Pods ios/Podfile.lock

# 4. Navigate into the iOS directory, install Pods, and then return to project root
#    `--repo-update` ensures your local CocoaPods spec repo is up-to-date
cd ios && pod install --repo-update && cd ..

# 5. Build your Flutter iOS application
flutter build ios
```

## Debugging Tips

*   **"CocoaPods could not find compatible versions..." error:**
    *   **`s.version` mismatch:** Double-check that the `s.version` in your `MteRelay.podspec` (within the `mte-relay-client-ios` repo at the specified Git tag) precisely matches the `:tag` value in your app's `Podfile`.
    *   **Cache issues:** If problems persist, consider `pod cache clean --all` in addition to the `rm -rf` commands, followed by the full clean and rebuild sequence.
    *   **Podspec validation:** Clone `mte-relay-client-ios.git`, `git checkout <your_tag>`, `cd <MteRelay.podspec_directory>`, and run `pod spec lint --verbose --allow-warnings` to get detailed errors about your `.podspec` itself.
*   **"Build input file cannot be found: ... Mte.o" error:**
    *   This often indicates issues with the `MteRelay` pod's internal build configuration or how it exposes its C components. Ensure your `MteRelay.podspec` correctly specifies `s.source_files`, `s.vendored_frameworks`, and `s.public_header_files` (if any, typically `Classes/Mte/include/*.h`).
    *   Make sure `pod_target_xcconfig` is properly setting `HEADER_SEARCH_PATHS` to include `Classes/Mte/include`.
*   **"Mixed language source files; feature not supported" error:**
    *   This error is typically associated with Swift Package Manager and specific target configurations. If encountered in a CocoaPods context with `MteRelay`, ensure your `MteRelay.podspec` correctly lists `s.source_files` paths and that all files it expects to compile are actually Swift, or if mixed, are handled appropriately for CocoaPods' build process.
